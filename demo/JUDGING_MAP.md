## Best Use of HydraDB award fit

- Strong graph data model: immutable evidence and lifecycle records are connected through explicit
  revision, call, impact, event, and supersession relationships.
- Novel retrieval or reasoning: recall checks whether evidence remains current after a committed
  change and withholds unsafe matches with a machine-readable reason.
- Interesting traversal: a changed leaf function can invalidate memory attached to an unchanged
  caller two or three edges away.
- Hard for a flat approach: direct-file matching misses cross-file callers. The checked baseline
  quantifies that loss instead of asking the judge to accept the claim.

## Supporting lenses, not separate published scores

The organizers do not separately publish insight value, data quality, utility, scalability,
verifiability, or ecosystem fit as scored dimensions. They still help explain the five official
criteria.

| Supporting lens | Evidence                                                                                                                                                                | Gap                                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Insight value   | Stale memory is a concrete failure mode developers already recognize when agents carry context across sessions.                                                         | The pitch should use one concrete wrong-claim example rather than broad claims about all agent memory.                                                     |
| Data quality    | The indexer uses compiler-resolved tracked TypeScript files and records unresolved calls instead of inventing edges. Memory carries exact Git and symbol provenance.    | Language coverage and repository diversity are intentionally narrow.                                                                                       |

## Four-sentence pitch

Coding agents keep useful repository facts long after the code changes, so stale memory can quietly
cause wrong edits in later sessions. FreshContext is a local HydraDB-backed memory safety layer for
coding agents. It indexes TypeScript symbols and call paths across Git commits, binds each memory to
code evidence, and uses HydraDB traversal to return current context through MCP or withhold it with
a proof path after the code changes. As persistent agent memory becomes standard developer
infrastructure, teams need continuity without letting yesterday's code assumptions control today's
work.
